## 1. 修正内容
### 予定の重複処理（ドラッグ・新規・編集で共通）
- `packages/domain/src/placement.ts`：保存前の重複判定 `checkPlacement`。対象は予定と未完了の時刻指定タスク、自分自身は除外。同じ日に空きがなければ翌日の候補を返す。既存予定は動かさない。
- `apps/web/src/app/usePlacementGuard.ts`：iOS風アラート「時間が重なっています」で次の3つから選ばせる。
  - 「12:15〜13:00 に移動／保存」（空き時間の候補）
  - 「重ねて移動／保存」
  - 「キャンセル」
- ドラッグ：指を離したあとも確認が終わるまで**仮位置だけ**を表示する。オレンジの輪郭で重なりを示し、控えめに脈打たせる。承認されたときだけ `repo.moveEvent / moveTask` を呼ぶ。キャンセルではリポジトリを一切呼ばないので、データも操作ログ・未同期キューも変わらない。重ならない移動は確認なしで保存する。
- 新規・編集：予定もタスクも、時刻を新しく決めた／変えたときは保存前に同じ確認を出す。キャンセルすると編集画面に戻る。
- iOS と同じく、アラートは背景タップで閉じない。

### 長押し進捗
- 初期値は**理想進捗率**。予定時刻がないタスクだけは、既存の実績（なければ0%）から始める。
- 指の横移動量を、画面上の実際のバー幅で割って反映する。浮いたセルの拡大率も考慮しているので、充填の端が指と同じ距離だけ動く（E2Eで誤差1.5px未満を確認）。
- セルは長押しで持ち上がり（拡大・影・角丸）、中身が緑のカプセルにスプリングで変形する。
- 100%で離すと確認する。キャンセル・ドラッグなし・pointercancel では変更しない（いずれも回帰テストあり）。

### ホーム
- タスク一覧は余白なし・カードなしで画面幅いっぱい（iOSリマインダー方式）。ホームの背景はシステム背景色、区切り線はインセット。時間軸の時刻欄を46→42pxにして予定の表示幅を広げた。
- ハンドル：pointercancel では開閉を確定せず元の状態へ戻す。指を離したときの判定は、直前約100msの速度を使う方式に変えた（全体平均ではなく）。
- 拡張時、実行中・次のタスクがなければカードも帯も出さず、カレンダーが上端まで広がる。

### カレンダー
- 月表示：週ごとに行を分け、日付をまたぐ予定は**途切れない1本のバー**で描く（`layoutWeekBars` で段を詰める）。週をまたぐ場合は端を角張らせて続きを示す。1日あたり最大4段まで表示し、超えた分は「+N」。
- 複数日表示：掴んだ列を基準に日付の移動量を決める。日付をまたぐ仮位置は、重なるすべての列に切り分けて描く。15分スナップは維持。
- ピンチ：再描画せず CSS 変数 `--hour` とスクロール位置だけを毎フレーム（requestAnimationFrame）更新し、指の間の時刻を固定したまま伸縮する。指を離した時点で倍率を確定する。トラックパッドのピンチも同じ処理。
- 時間軸上のタスクは、静止長押しでは何も出さない。編集・削除はタップ後の詳細シートから行う。予定の静止長押しメニューは仕様どおり残している。

### 検証中に見つけて直した不具合
- **メニューを閉じた直後のタップが無視される**：閉じるアニメーション中のメニュー背面がタップを吸い込んでいた。閉じかけのメニュー・シート・アラートはタップを透過し、`inert` にした。
- **自動スクロールが手動スクロールを上書きする**：時間軸の「現在時刻へ合わせる」処理が、手動やプログラムによるスクロールの後にも位置を戻していた。
- **キーボード表示中にシート下部が隠れる**：`visualViewport` でキーボードの高さを取り、その分シートを持ち上げるようにした。

## 3. テスト結果（実測：2026-10-31 22時台）
| 項目 | 成功 | 失敗 | スキップ |
|---|---|---|---|
| `pnpm typecheck` | 成功 | — | — |
| `pnpm lint` | 成功（エラー・警告0） | — | — |
| `pnpm test`（Vitest） | 46 | 0 | 0 |
| `pnpm build` | 成功 | — | — |
| Playwright Chromium（393×852・モバイル・CDPタッチ） | 43 | 0 | 0 |
| Playwright WebKit（393×852） | 39 | 0 | 4 |

追加した回帰テスト：
- Vitest 10件：重複判定5、月表示バー3、浮遊カード2
- E2E 17件：`phase1-review.spec.ts` 16件と、オフラインでの編集1件

WebKit でスキップした4件と理由：
- タッチの pointercancel（進捗・ハンドル）2件、2本指ピンチ1件：CDP のタッチ入力が必要で、WebKit では使えない
- オフライン再読み込み1件：Linux 版 WebKit の制限で実行できない

実行環境についての補足：
- 公開時の GitHub Actions でも、Chromium と WebKit の E2E に合格したビルドだけを公開する。
- E2E の一部ではページの時計を固定しているため、アラートの表示アニメーションの開始が遅れる（実時刻では約0.2秒で表示されることを確認済み）。
