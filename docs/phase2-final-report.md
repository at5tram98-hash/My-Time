**クラウド連携（本番で動作）**
- Google ログイン（OAuth 認可コード + PKCE、ID トークン検証、ログインを始めたブラウザだけ受け付ける CSRF 対策、HttpOnly セッション）。権限は `openid` `email` `profile` `drive.file` の4つだけ。

- 端末のデータはアカウントごとに分離。ログイン前のデータは「件数と移行先」を見せて本人が選んだときだけコピー（原本は端末に残す）。

- 復元試験（Drive から読み戻し、復元したら現在のデータと一致するかを1件ずつ比較。データは変えない）。
- 30日後の期限削除（バックアップ確認・アーカイブ確認のゲート付き）。**本番は `RETENTION_MODE=off`（停止）**。
- 期間指定の復元（アーカイブから一時表示、「閲覧を終了」で外す。Drive の原本は残る）。
- Web Push 通知（RFC 8291 + VAPID）、5分ごとの通知判定。
- 旧 GitHub Pages 版からのデータ移行（「その他 → データの移行」でファイル書き出し・取り込み）。

## 3. 変更ファイル／主要な設計判断

- 構成：`apps/web`（React + Dexie PWA）、`apps/api`（Hono + Cloudflare Workers + D1）、`packages/domain`（純粋関数）、`packages/contracts`（Zod）。
- D1 マイグレーション：`0001`〜`0004`（すべて追加のみ）。本番適用済み。
- 主要な設計判断（詳細は ADR 0002）：
  - 削除（tombstone）は端末の更新日時・版より常に優先し、記録の復活は `/restore` だけが行う。
  - 書き込みは条件付き更新＋トリガーでカーソルを同じトランザクションで採番（同時実行・応答喪失に強い）。
  - 拒否・競合した端末の内容は recovery ストアへ退避し、黙って捨てない。
  - 端末の保存領域はアカウントごと（`my-time@<ユーザーID>`）、API の所有者は「そのタブで表示中の領域」に固定し、サーバーでもセッションと照合。
  - 期限削除の前提は「その日の日次バックアップの読み戻し確認」＋「対象のアーカイブの読み戻し確認」。本番の初期値は off。
  - 本番公開は main からの手動ワークフローのみ（確認文字列「公開する」、専用 D1・正しい URL に限定、`RETENTION_MODE=off` 固定、全テスト合格が条件）。
