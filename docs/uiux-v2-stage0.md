## 構造の現状

- **画面**：5つのタブはそれぞれ次のファイルにある。HomeScreen / CalendarScreen / TasksScreen / AnalysisScreen / OtherScreen。
- **シート**：`SheetHost` が SheetState のスタックを描画する。シートの高さは1段だけで、下へ引くと閉じる。
- **編集画面**：タスクと予定で別々の画面になっている（TaskEditorSheet / EventEditorSheet）。＋はメニューから種類を選ぶ方式。
- **データ**：Dexie v3（端末）と D1 の records（data は JSON 文字列）。同期のスキーマは zod で、**知らない項目は取り除かれる**。そのため新しい項目を足すときは、契約（contracts）にも足す必要がある。
- **エンティティ**：calendar / event / task / subtask / subject / employer の6種類。新しい種類を足すときは、contracts、API のバックアップ・復旧、クライアントの DATA_TABLES、Dexie の版を同時に更新する。

## 方針（データ）

- 予定とタスクの拡張項目は、任意の `extra` オブジェクト1つにまとめて追加する（`extra` 自体を省略できる）。
  - 中身：終日、色、場所、移動時間、会議 URL、複数の通知、URL 一覧、添付ファイル、Studio の種類と値。
  - 古いデータは `extra` がない状態として読み、書き換えない。
- 新しいエンティティを2つ足す。
  - `studioType`：自作の種類。定義の版と変更履歴を含む。
  - `category`：タスクのカテゴリー。名前・アイコン・色・並び順を持つ。
  - どちらも同期・バックアップ・復旧の対象にする。古いクライアントは知らないエンティティを無視する。
- 設定に足す項目：ホームの分割比率、カレンダーの 3日表示、タスクの並び順と絞り込み、分析の目標、最近使ったアイコンと色。いずれもアカウントごとの設定として保存する。

**不能・保証できないこと**（PWA の制約）

- 指先への振動（触覚）：iOS Safari は `navigator.vibrate` に対応していない。
- バックグラウンドでの AR の自動開始：アプリを閉じている間は動かない。サーバーからの通知でお知らせするだけになる。
- 通知の届く時刻：正確な時刻は保証できない。
