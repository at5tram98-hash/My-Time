## 1. 実装した機能（実際に操作できるもの）

**画面と導線**
- 下部タブを **今日・カレンダー・タスク・振り返り** の4つにし、右に丸い「追加」ボタンを置いた。
- 設定は各画面右上の歯車から、右から重ねて開く。「戻る」・左端の右スワイプ・タブのタップで閉じる。同期の「!」は歯車に付く。
- **今日**は1日だけ（1日/2日の切替を廃止）。上から順に、今やること（1枚）、状況チップ（注意・未割当・タスク・余白）、**左＝予定・右＝タスク**のレーン。
  - レーンの幅は見出しのタップで3段階に変えられる。
  - 予定の移動時間は斜線で、作業枠は破線で、確認タスクは丸いピルで描く。予定につながる準備には予定の色の線を付ける。
- 旧ホームの上下分割・つまみ・コンパクト表示は廃止した。長押しの進捗入力は「今日のタスク」一覧（タスクのチップから開く）と「タスク」タブで使える。

**入力（P01〜P05。端末内の規則で動く。外部へは送らない）**
- ＋を押して文章を書くと、予定・タスクの候補に分かれる。曖昧な時刻は「候補」として扱い、どう読み取ったかの根拠を付ける。準備や作業枠も一緒に提案する。
- 候補を選んで追加でき、直後なら取り消せる。
- 「来週のバイト」のような書き方は検索になる。「〜を1時間遅らせて」は変更の差分を見せる。「今日の課題を移して」は組み直しの案を出す。
- 種類のタイル（25種類）や、詳しい編集画面への切り替えもできる。

**専門の種類 S01〜S25**
- 編集画面の「種類」から選んだときだけ、専用の項目が出る。
- 情報シートには専門カードを表示する。給与見込み・残り作業・出発の目安・営業時間の未確認などの要点を出し、「詳しく」でチェックや記録をその場で操作できる。
- 工程・準備・買い物の自動作成は、同じものを二重に作らない。
- 詳細は提案書 §10 の対応表を参照。

**計画の支援（P06〜P10・P21〜P30）**
- 「気づいたこと」：重なり・二重登録・移動不足・遅刻の恐れ・期限の不足・作業時間が決まっていない・前のタスクが未完了・詰め込みを、理由と確かさを付けて示す。
- 修正案は変更前→変更後の差分で示し、適用してから約6秒は取り消せる。別の操作で値が変わっていた場合は適用しない。
- そのほか：未割当、延期（期限は変えない）、分けて進める、時間をずらすボタン、次の行動、前提タスク、移動の時間（バッファ）。

**振り返り（P31〜P40）**
- 今日の振り返り、余白、見積の精度、7日間の余白、期限の集中、課題の残り負荷、混み具合（確定した予定と見込みのタスクを分けて表示）、今月の給与見込み、時間の使い方、集中しやすい時間帯。
- 記録が足りないときは値を出さない。

**基盤（P15・P17〜P19・P41〜P48・P50）**
- 予定の書き出し（.ics）。
- 同期で守った変更の一覧。
- 入力元・最終更新・送信待ちの表示。
- 同じ内容の通知を1件にまとめる。出発の時刻の通知。通知を控える時間（サーバーの Push にも反映）。
- ホーム画面のショートカット・URL から開く。
- 長押しメニューに延期と完了の取り消し。
- 自然な言い方での検索。
- 変更履歴と、そこから戻す操作。
- キーボードの近道（n・t・/）。

## 2. 実装しなかったこと・制限（隠さない）

- **ChatGPT連携**（AIによる解釈・提案、P49）と、**TimeTree・シフトボード・Google/Apple カレンダー・My Money との連携**（P11〜P14、S03・S24 の連携部分）は、指示どおり実装していない。
- 文章の読み取りは規則で行う。想定していない書き方は読み取れない（読み取れないと案内する）。
- 祝日の判定、店の営業時間の取得、交通情報は使っていない。分からないものは未入力・未確認として表示する。
- iPhone 実機（Safari・ホーム画面に追加した PWA・VoiceOver・指の追従・ショートカット・Push）は**未検証**。
- 旧ホームを撮影していた過去の画面キャプチャ用 spec（`screens.spec.ts`・`capture-v2/v3/phase3`）は、廃止した操作（つまみ・1日/2日切替）を含むため、そのままでは動かない。CI の合否からは元から除外している。過去の画像は記録として残した。

## 3. 主な変更ファイル

| 区分 | ファイル |
|---|---|
| ドメイン（純粋関数） | `packages/domain/src/spec.ts`（25種類）・`planner.ts`（空き時間・検知・案・振り返り）・`nlparse.ts`（文章の読み取り）・`ops.ts`（通知の静穏時間・出発・重複除去）・`importParse.ts`（ICS の書き出し）・`types.ts` |
| 契約 | `packages/contracts/src/index.ts`（`extra.spec`・`dependsOn`・`origin`。すべて任意なので旧データ・旧クライアントと互換） |
| 保存 | `apps/web/src/data/repo.ts`（applyPlan/revertPlan、createFromCandidates/undoCreated、種類の工程・準備・買い物、変更前の内容の記録と rollback、繰り返しの二重作成防止）・`db.ts`（設定の追加。DB の版は変えていない） |
| 画面 | `features/home/HomeScreen.tsx`（今日）・`features/quickadd/`・`features/plan/`・`features/spec/`・`features/analysis/PlanningInsights.tsx`・`features/other/HistoryPages.tsx`・`SettingsButton.tsx`・`timeline/Timeline.tsx`（レーン）・`app/App.tsx`・`ui/TabBar.tsx`・`ui/undo.tsx`・`styles/today.css` |
| サーバー | `apps/api/src/jobs/notify.ts`（同期された設定の静穏時間・出発の通知を Push に反映）。**本番の Worker には反映していない** |

設計判断の要点：
- 予定とタスクは別の表のまま、共通の「種類」（`extra.spec`）で専門性を足した。DB の移行は不要で、旧データは表示時に読み替えるだけ。
- 提案はすべて差分（`Change`）として作る。保存は承認したときに1トランザクションで行い、取り消しも差分から戻す。時間の決まった予定は自動では動かさない。
